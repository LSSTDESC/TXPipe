Cluster Files
=============

The TXPipe core is focused on 3x2pt (lensing + clustering) measurements, but the CLMM packages runs of its data selection steps within TXPipe. The files these stages use are described here.


Cluster Catalogs
----------------

Cluster catalogs are generated by cluster-finding algorithms like RedMapper (which are currently not run within TXPipe). They are an input to the stages in `txpipe/extensions/clmm`.

==========  =============  ==========  =========
Group       Name           Kind        Meaning
==========  =============  ==========  =========
clusters    cluster_id     int64
clusters    ra             float64
clusters    dec            float64
clusters    redshift       float64
clusters    redshift_err   float64
clusters    richness       float64
clusters    richness_err   float64
clusters    scaleval       float64
==========  =============  ==========  =========


Cluster Source Selection
------------------------

The cluster source selection file (`cluster_shear_selection`) is generated in the `CLClusterSourceSelect` stage. For each cluster, it lists the source galaxies which are nearby and behind that cluster: the index into the original shear catalog and the distance from the cluster. The shears, weights and tangential and cross components of these sources are computed by `CLClusterEnsembleProfiles`, which saves them in `cluster_source_quantities`.

The file contains a table of clusters, and for each of those clusters, an index into another table of source galaxies. The columns are:

The `catalog` group is a list of clusters, matching the order in the cluster catalog which this came from.

The `index` group is a list of galaxies around clusters, sorted by cluster and, for each cluster, by their row in the shear catalog.

=======  ========================  ==========  =========
Group    Name                      Kind        Meaning
=======  ========================  ==========  =========
catalog  cluster_id                1D int64    The ID number from a cluster in the cluster catalog.
catalog  cluster_sample_start      1D int64    The row in the `index` catalog where galaxies around this cluster start.
catalog  cluster_sample_count      1D int64    The number of rows in the `index` catalog for galaxies around this cluster.
catalog  cluster_theta_max_arcmin  1D float64  The maximum distance from the cluster center of included galaxies.
index    cluster_index             1D int64    The row in the `catalog` group where the cluster this galaxy is around is.
index    cluster_id                1D int64    The ID number of that cluster.
index    source_index              1D int64    The row of this galaxy in the original shear catalog.
index    distance_arcmin           1D float64  The distance from the cluster center to this galaxy in arcminutes.
=======  ========================  ==========  =========

With `variant_pairs`, the file also has the groups `catalog_<v>` and `index_<v>`, with the same columns, for each sheared version `v` of the shear catalog (1p, 1m, 2p, 2m; 1p, 1m for scalar metadetect). The pairs of a version are found with its own positions, cuts, tomographic bin and redshift, and are only used by `CLClusterShearCalibrator`, for the selection response.


Cluster Shear Response
----------------------

The cluster shear response file (`cluster_shear_response`) is generated in the optional `CLClusterShearCalibrator` stage. It has the shear response of the background sources of each cluster stack (a redshift and richness bin of `cluster_catalog_tomography`), from their pairs in `cluster_shear_selection` within the radial range of the stage. `CLClusterEnsembleProfiles` applies it with `shear_calibration: cluster_stack`.

The response is a 2x2 matrix for metadetect, and a single value for scalar metadetect and AnaCal. With `radial_calibration`, there is one response for each radial bin of the stack (first axis), NaN for the radial bins without sources.

===========================  ========================  ===========  =========
Group                        Name                      Kind         Meaning
===========================  ========================  ===========  =========
calibration                  catalog_type              attribute    The type of the shear catalog.
calibration                  radial_calibration        attribute    Whether there is one response per radial bin.
calibration                  distance_bins             attribute    The edges of the radial bins.
calibration                  bin_units                 attribute    The units of the radial bins, mpc or arcmin.
calibration                  n_bootstrap               attribute    The number of bootstrap resamplings of the clusters for the errors.
calibration                  stacks_without_sources    attribute    The stacks with no sources in the radial range, which have no response.
calibration/<stack>          cluster_id                int64        The clusters of the stack, to check the binning of the next stage.
calibration/<stack>          R                         float64      The response of the stack.
calibration/<stack>          R_err                     float64      Its bootstrap error (NaN without bootstrap).
calibration/<stack>          n_clusters                attribute    The number of clusters in the stack.
calibration/<stack>          n_sources                 attribute    The number of cluster-source pairs used.
calibration/<stack>          n_sources_per_radial_bin  attribute    The number of pairs in each radial bin.
===========================  ========================  ===========  =========

Each `calibration/<stack>` group also has the attributes of the stack in `cluster_catalog_tomography` (its redshift and richness edges). A stack without sources has no `R` and `R_err`.
